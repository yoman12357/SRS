# Adopted professor-brief contract

The exact supplied brief is retained in the original local workspace. The public
checkout documents its adopted scope below. The approved project applies its requirements
engineering workflow to cybersecurity/networking, rather than the financial
examples. No banking regulations are implicit requirements.

| Brief items | Local deliverable and completion evidence |
| --- | --- |
| 1–3: scope, stakeholders, input sources | Informal descriptions, question-bound answers and private references; exact source evidence; inferred roles/domain; visible unknown decisions. |
| 4: multi-agent architecture | One coordinator and sequential schema-bound section specialists using local Ollama. Shared context is validated JSON, not raw conversations copied indiscriminately. |
| 5–6: knowledge and retrieval | Copied, hashed cybersecurity corpus; local Chroma/nomic retrieval; literal source-bound citations; applicability review. Guidance cannot become a confirmed user decision. |
| 7–10: gathering, extraction, classification, quality | Adaptive questions, priorities/dependencies, overlapping dimensions, observable authored acceptance, source fidelity, contradiction/omission checks, explicit unresolved issues. |
| 11–12: controls and linked artifacts | Security/privacy/compliance applicability, source-backed mappings where specified, stories/use cases, architecture, threats, risks, tests and deterministic traceability. No invented regulation or legal determination. |
| 13–15: lifecycle selection | Versioned deterministic evidence rules, ranked suitability points and local model explanation; project-specific phases with roles, deliverables, entry/exit criteria, security checks and human gates. |
| 16: oversight | Exact-content hash reviews, immutable revisions, accept/reject/request changes, regeneration and distinct draft/approved exports. Model generation and test harnesses never record human approval. |
| 17–18: safe local prototype | Loopback-only inference, no telemetry, project isolation, bounded uploads, untrusted-reference boundary, no execution or infrastructure-changing agent tools. |
| 19–20: evaluation and improvement | Two real cybersecurity cases, source-by-source output review, PDF inspection, matched base/adapter evaluation, frozen dataset provenance and reproducible local commands. Record actual failures and limitations. |

The original governance retains single-user local deployment. Enterprise RBAC,
MFA, cloud encryption/hosting, regulatory certification, stakeholder satisfaction
studies and comparison with human analysts require separate implementation or
research evidence; they are not claimed here. This boundary does not excuse
missing SRS artifacts or incorrect SDLC recommendations in the authorized scope.

Status: **not complete**. Automated checks establish selected invariants, not
semantic correctness. `VALIDATION.md` and live evaluation artifacts record what
has actually passed. Final completion requires the original objective, including
real outputs and document review, rather than only mocked test success.
