# ADR-0023: Keep open planning decisions out of product behavior and design proposals explicit

2026-10-27. The frozen profile-1.19 campus run converted the explicit undecided
budget/schedule/threshold/framework passage into a runtime requirement to reject
budget proposals. Architecture then failed trying to cover that invented feature.
Its parsed design also called inferred components confirmed, added real-time
commitments and logged isolation actions outside the policy-change logging scope.

Extend project-context recognition to explicit open planning-parameter declarations.
Analysis grammar routes those passages to introduction/SDLC; independent section
validation rejects a product requirement based only on project context, including
old cached analysis. Preserve those decisions in the existing literal scope/open
decision register. The word "unknown" in a genuine unknown-host access rule does
not make it project metadata.

Architectural realization artifacts remain proposed until separately reviewed;
this provenance status does not downgrade confirmed requirements or source facts.
Constrain their status during generation and validate it on read/edit as well.
Reject unrequested real-time commitments and audit/logging responsibilities whose
linked requirements/evidence do not require logging. This catches the observed
expansions; it is not a complete natural-language entailment proof.

These changes are integrated in profile sequential-1.20 and covered by tests.
Real document correctness and PDF review remain open gates, not inferred from tests.

The same VPN review found that the employee-specific MFA source became a statement
for every approved-service user. The explicit-authentication actor guard retains
the stated employee scope instead of inferring authentication for other roles.
