# ADR-0016: Keep introduction facts as literal stakeholder evidence

2026-10-27. The real HTTP VPN run added an unsupported fixed release cycle,
expanded contractor restrictions and asked about accepting excluded functionality.
Its planning-capacity validator also confused two separate quantities in one claim.

The introduction specialist still authors the overview and headings, but its fact
items select literal source passages instead of rewriting them as new obligations.
The decoder restricts item details to supplied passages and validation verifies the
evidence/detail pairing. Open decisions come from the existing analysis rather than
a second round of invented questions. Protected source scope remains independently
preserved. This applies only to the introduction; requirements and acceptance
criteria remain model authored and must pass their existing gates.

Planning-capacity checks bind the quantity to the active/concurrent subject instead
of combining unrelated numbers and capacity words anywhere in the same claim.
Regression cases retain rejection of an invented active cap while allowing a
registered population alongside a separately stated session capacity.

These changes do not establish semantic correctness of summaries or later sections.
Real document review remains a completion gate.

Profile 1.18 selected a literal audit statement under a misleading "Project
purpose" heading and omitted the explicit budget/framework unknowns. Profile
1.19 uses neutral source-bound headings and independently projects explicit
unresolved passages into both the fact register and open-decision list. It does
not generate new facts, new obligations or a stakeholder answer.
