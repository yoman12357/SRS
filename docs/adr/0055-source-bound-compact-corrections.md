# ADR-0055: Source-bound correction for compact requirement batches

The four supplied live examples exposed two coverage false positives: a purpose's
"managed endpoints" qualifier was counted as a management action, and collection
of system events was not recognized as a monitoring product's stated behavior.
Preserve genuine management and monitoring obligations while accepting those
source-equivalent purpose expressions. Negative or unrelated collection remains
uncovered.

The firewall batch also moved neighboring passages' actions between source IDs.
After ordinary bounded authoring/correction, permit a model-authored replacement
only for a source group with recognized missing behavior, absent normative modal,
or a project-request verb recast as runtime behavior. The repair schema requires
the statement to begin with "The system shall ". A request to design a system does not require
the product to design itself. Valid neighboring groups stay frozen; the correction
schema cannot name them. Existing field-only test corrections remain field-only.
Every merged candidate passes the complete original validator. Unsupported errors,
deadline expiry and unsuccessful repair remain explicit failures. Never replace
the model response or a failed run with invented successful content.

Use the same section deadline, local provider, configured adapter/base correction
policy and public Document schema. Record repaired source IDs, actual model and
attempt counts. The profile is sequential-1.30, source-batch-1.3 and
source-grounding-1.15. No new provider, API endpoint or configuration is introduced.
Historical canonical content is unchanged and is rechecked under current rules.

Regression tests cover the false positives and negative controls, frozen valid
siblings, rejection of incomplete repairs, explicit design-tool behavior and
the full request-verb validator/correction path. Actual live run evidence is
retained under demo/four-examples-20261029; completion and content quality are
reported separately.
