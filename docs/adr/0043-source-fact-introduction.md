# ADR-0043: Compose the introduction from exact source facts

Both recent full VPN runs failed because a free introductory summary changed
planning population or stated simultaneous load into an upper cap. The trained-
first summary also reopened continuous delivery despite the explicit "No continuous
delivery" source statement. Corrective retries kept copying the invalid paragraph.

The introduction specialist will ask the trained local model to organize the
complete source evidence inventory. Bind a complete unique source-ID order in its
internal JSON schema; reject unknown, duplicate or omitted facts independently.
Compose the public introduction from exact source quotations, their source-backed
status, and the existing unresolved-decision inventory. Use a factual document-
purpose overview instead of another generative paraphrase of product obligations.
Preserve question context on clarification-response titles. No source fact or
label is changed to make generation pass; canonical requirements/criteria remain
separate model-authored artifacts.

Exact short answers such as "Yes" must not be padded into fabricated sentences.
Permit short nonempty narrative text in the schema, while independently retaining
the old eight-character narrative rule everywhere except an exact introduction
quotation. A copied question-context title is source metadata, not a newly
asserted quantitative commitment; other title text remains source-validated.

Reuse the existing scope/unknown/exclusion projection helper through a pure source-
facts module, retaining its public validation import for compatibility. Version
automatic introduction provenance independently; current quality checks verify the
claimed view. Legacy unchanged-input retries refresh introduction and dependent
SDLC only, while other revalidated artifacts remain unchanged. Reviewed introduction
edits keep their existing endpoint and source gates, with honest edit provenance.

The public narrative shape and PDF layout remain compatible; optional document
provenance is added. The model still performs the introduction's organization
task, and the runtime records its actual tag/attempts. No provider/framework,
training, dataset-label or human-approval change is introduced.

Implemented as source-fact-introduction-1.0 / source-grounding-1.8. The helper's
body was moved without changing its behavior; its validation import is retained.
Tests cover exact quantities and no-CD decisions, unknown/exclusion status, short
bound answers, copied context, invalid orders, claimed-view tampering, selective
retry and honest edit provenance. Focused 11 tests, baseline 55 tests, staged and
main full 353 tests passed; Ruff passed. Actual full trained-first verification
is running in data/evaluations/20261028-090128-finetuned. No completed SRS or SDLC
is inferred from the software checks.

The 090128 run terminated on an introduction native-schema KeyError before model
inference. The schema-kind guard and actual assigned-section regression were
fixed; full 353 tests passed. Separate resumed 090700-native-fix run completed both
source-fact introductions on the adapter, then failed in functional requirements.
No full SRS or SDLC correctness claim follows.
