# ADR-0048: Give a single-requirement completion a fresh subtask context

The actual VPN E-006 capacity completion inherited full-section instructions and
fields, including array-oriented completion instructions and a permission-
management instruction even though the missing item was 25 simultaneous sessions.
Its responses continued with additional Requirement objects after the first.
The strict terminal-padding experiment correctly rejected this meaningful suffix;
discarding it would silently discard model content.

Build a fresh single-Requirement context instead of merging bulk section context.
Retain the exact target source, compact canonical ID/statement index, exact source
exclusions/unknowns and the actual missing actions/metrics. Ask for one object with
observable authored criteria. Do not inherit category arrays, unrelated acceptance
contracts, previous section drafting instructions or management instructions for a
capacity subtask. External guidance does not create new source obligations here.

For recognized unqualified integer concurrent/simultaneous loads, mechanically
constrain the additional statement to support that exact source phrase. Never
convert registered inventory into concurrency, add a maximum or infer a bound.
Explicit bounds or uncertainty do not use this narrow shortcut. Preserve the
existing permission-management source constraint under a generic completion key.
The complete source/criterion gate still applies after native decoding.
