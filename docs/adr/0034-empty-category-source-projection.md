# ADR-0034: Bind empty-category explanations to actual canonical coverage

The profile-1.27 campus run passed functional generation, then its empty
nonfunctional section invented a malicious-device exclusion and referenced
"Device Isolation" control "E-12". Neither rule nor control exists in the source
or canonical registry. Free-form inapplicability prose can add obligations even
when the requirements array is empty.

For a category with no uncovered source obligation, derive a small metadata
object from the actual canonical IDs assigned to that category's evidence.
The explanation states only that this section introduces no separate obligation.
The specialist sees the complete compact canonical inventory and selects relevant
existing IDs, including controls omitted from its initial category routing. IDs
already assigned to this category remain required links. Do not infer absence of
network behavior merely because initial classification omitted a network label.
The explanation cannot name
new product behavior, actors, regulations, technologies or controls.

The section specialist still asks the trained local model and returns validated
JSON. Bind the explanation and the actual canonical ID vocabulary in its native output schema,
forbid new rows or supplementary tests in this no-gap call, and independently
validate the echoed metadata after parsing. Do not silently replace a rejected
model response. Normal requirement and acceptance authoring remain generative.
Explicit reviewed edits remain separately versioned and source-validated.

Version this projection separately from the main generation instructions. When
resuming unchanged inputs, refresh a valid empty automatic checkpoint from the
older metadata policy without re-authoring unchanged canonical behavior or
invalidating downstream artifacts that never consume applicability prose. Every
reused artifact still passes current validation. Invalid/nonempty checkpoints
retain ordinary regeneration behavior. Store the metadata version in document
provenance and private run checkpoints; historical content/hashes stay immutable.

This is a deterministic factual coverage explanation, not a new SRS template,
fabricated requirement, omitted applicable section or human approval. Schema
binding does not establish that upstream extraction/classification was complete;
the normal source-coverage and semantic-review gates remain required.

The first real native-decoder probe used the factual explanation but selected no
network links. Metadata policy 1.1 therefore also requires canonical IDs whose
statements/dimensions explicitly establish the category topic. Titles and rationale
do not create those anchors. Additional links still come from the model's selection
of actual IDs, and the shared parser gate checks all required links independently
of native decoding. This is an index of existing behavior, not a new obligation.

Integrated verification: 301 backend tests passed; Ruff passed. The second real
probe selected the known network controls on its first adapter attempt. Complete
document semantics and SDLC output still require separate review; this bounded
metadata result does not establish a correct SRS.
